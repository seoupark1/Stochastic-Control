**What I implemented**
1) 기존에 tracking을 위해 필요한 reference 데이터를 body state 계산을 돌리며 같이 계산했었다. 이 방법의 문제점은 이미 다 알고 있는 reference attitude와 trajectory를 특정 t에 대해 그때그때 계산하니 불필요한 연산이 늘어난다는 것이다. 따라서 reference 데이터를 외부에서 가져오도록 하는 provider를 제작했다. 현재 코드는 reference 함수를 대입하면 mrp attitude, 각속도, 각가속도를 시간 t에 대해 get_reference 메소드를 통해 반환하는 형태이다. Provider 구조의 장점을 더욱 활용한다면 reference의 state를 csv 파일로 읽는 방식으로도 확장할 수 있다.

2) 이 프로젝트는 회전운동에 집중한다. 그러므로 사용하는 상태벡터는 mrp(혹은 quaternion), 각속도의 2가지이다. 그러나 gravity gradient torque를 반환하는 함수를 제작하면서 불가피하게 body의 위치와 속도를 요구하는 경우가 있다는 사실을 알게되었다. 그러나 외란 몇 종류를 계산하기 위해서 병진운동 state까지 포함시키는 것은 불필요하다고 생각했다. 그래서 만들게 된 것이 StateProvider와 context이다. 시간 t일 때 body의 attitude, omega, position, velocity 정보를 모두 담은 context는 build_context를 위해 attitude와 omega는 필수적으로 요구하지만, position과 velocity는 None을 기본값으로 해 선택적으로 받는다. 따라서 병진운동 정보가 필요할 때는 context를 만들고, 평상시에는 state를 사용하면 된다. Context는 각 state vectors가 저장된 순서를 기억할 필요없이 .position_N, .attitude_BN 의 방식으로 값을 불러올 수 있다는 것도 장점이다.

3) Sensor에서 estimator, estimator에서 controller로 과정이 진행됨에 따라 각 장치들이 접근 불가능한 정보가 있다는 사실을 알게 되었다. 예를 들어, controller는 어떤 외란을 받는지 그 종류를 알지 못한다. 이 흐름을 깨달으니 원래 폴더 종류에 상관없이 상태벡터의 변수명을 'state'로 통일했었는데, controller에는 true state이 아닌 estimator에서 넘어온 'estimated_state'를 사용해야 한다는 사실을 알게 되어 수정했다.

4) Lyapunov Integral Controller는 내부에서 적분을 하지 않고 각 time step에서의 control vector와 eta_dot을 내놓도록 만들었다. 외부 solve_ivp는 sigma_dot, omega_dot, eta_dot에 해당하는 9개의 요소로 구성된 state를 적분한다. 여기서 eta_dot의 적분값이 누적 자세오차가 되어 integral control vector 계산 식에 들어간다.
